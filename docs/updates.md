# 更新与发布

软件在启动或返回前台时检查公开 GitHub Release，自动检查间隔至少 6 小时；「我的」可随时手动检查、关闭自动检查或修改来源。软件完全退出时不后台轮询，提醒显示在软件首页及更新中心。

默认官方发布源为 `9OwO6/The-Last`，无需用户手动配置。首次从历史版本升级到 0.11.0 时需要手动覆盖安装一次，之后可通过软件内更新中心获取新版。

发布约定：

1. 修改 `app/build.gradle.kts` 的 `versionName` 和递增的 `versionCode`。
2. 使用 `v主版本.次版本.修订号` 标签创建正式 Release，附更新说明；不读取草稿与预发布版本。
3. 每个正式 Release 只附一个通用 APK。GitHub API 的资产 `digest` 必须提供 SHA-256。
4. 包名必须保持 `com.thelast.app`，签名必须与已安装版本一致。APK 的版本名称需等于标签，版本码必须更高。
5. 本地运行 `gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`，再核对签名及 SHA-256 后上传。CI 只验证代码，不发布使用临时密钥签名的安装包。

提交并推送后，可用 `powershell -ExecutionPolicy Bypass -File scripts/publish-release.ps1 -NotesFile docs/release-notes-0.11.0.md` 发布。脚本会检查干净工作区、远程提交、已有版本、测试、构建和历史签名，再附上 APK 与 SHA256.txt 创建正式 Release。后续版本使用对应的新说明文件。

当前历史安装包 0.10.0 使用本机 Android debug 签名。为允许覆盖安装保留用户数据，0.11.0 继续使用相同签名；这是供个人侧载的构建。签名证书 SHA-256 为 `35bcb314aa2e4b781a9ab0ef6c92b5a8525dc530b43d020c5f2bfc38220c6eba`。本机 `~/.android/debug.keystore` 必须妥善保留且不得上传仓库；其他电脑或 CI 默认生成的 debug key 无法覆盖此安装。未来如迁移正式签名，需要先设计数据迁移路径。

下载在软件进程内完成，支持显示进度与失败后重试。安装前验证完整性、包名、版本和签名；安装由 Android 系统确认。首次可能需要允许「安装未知应用」，授权后返回再点击安装。缓存安装包不参与系统备份。

私有仓库不能直接使用本功能；不得在 Android 中嵌入 GitHub token。如需私有发布，应先添加经过身份验证的服务端下载代理。

人工验收：

- 覆盖安装后原有事项和历史仍在；首页、日历、统计及主题切换正常。
- 手动检查当前版本应显示「已经是最新版本」。发布更高版本后，重新手动检查应出现首页提醒。
- 查看更新说明，下载并确认进度；断网时显示失败，联网后可重试。
- 验证未知来源权限往返及系统安装确认；安装完成后版本号正确，记录仍保留。
- 关闭自动检查后，返回前台不自动请求，手动检查仍可使用。
